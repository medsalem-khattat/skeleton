# Changelog

## 1.1.0 — unreleased

Deployment model: every deployment has its own Firebase project, owned and
billed by the customer. See [docs/CUSTOMER_DEPLOYMENT.md](docs/CUSTOMER_DEPLOYMENT.md).

### Deployment

- Each deployment is one file, `deployments/<id>/deployment.json`, plus its
  public Firebase client files in `deployments/<id>/firebase/`.
- New `tool/deployment.mjs` (`list`, `check`, `use`, `deploy-backend`)
  validates a deployment, scans it for secrets, and generates the app's
  Dart defines, Firebase files, Android application ID/label/App Links host,
  and iOS bundle ID/display name/associated domain.
- The Firebase client files are no longer committed in `frontend/`; they are
  generated by `use`. Run `node tool/deployment.mjs use <id>` after pulling.
- Builds take `--dart-define-from-file=deployment.g.json`.
- New `example` deployment with placeholder values for tests, CI, and the
  local emulators; the previous configuration is the `dev` deployment.
- Secrets live only in the customer's accounts and Codemagic team (groups
  `deployment`, `firebase_deploy`, `ios_signing`; keystore
  `upload_keystore`). See [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

### Backend

- New `recordPasswordChange` callable writes the password-change inbox record;
  clients can no longer create inbox records.
- Push notifications use the user's app language (English or French).
- New `cleanupDeletedUser` Auth trigger removes user data when an account is
  deleted outside the app; `deleteAccount` is safe to retry.
- Firestore rules allow owners to write only `name`, `email`,
  `photoStoragePath`, and `notificationsEnabled` on their profile, and no
  longer allow deleting it.
- Functions unit tests (`npm test`).
- `backend/.firebaserc` removed: every deploy must pass `--project`.
  `npm run deploy` now deploys Functions and both rulesets.

### App

- The drawer shows the installed version from the package metadata.
- Removed the unused `firebase_analytics` dependency.

### CI

- New `frontend-ci` workflow runs analyze and tests on push and PR.
- `backend-ci` also runs the Functions unit tests.
- `backend-deploy` is manual and refuses to deploy when the deploy
  credential belongs to a different project than the deployment file.
- `ios-release` fetches signing files for the deployment's app ID with the
  Codemagic CLI and publishes with the customer's App Store Connect API key.
- Release builds take the version from `pubspec.yaml` only.
- `backend-deploy`, `android-release`, and `ios-release` build a customer
  deployment only from the release tag `v<version>` (`node tool/deployment.mjs
  release-check`). Deployments marked `"internal": true` (`dev`, `test`,
  `example`) may build any commit.

### Upgrade order

Deploy the backend before releasing the app: the new app calls
`recordPasswordChange`, and the new rules reject the old app's direct inbox
write.
